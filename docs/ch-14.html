基础内容 (Foundation Topics)

IPv6 设计考量

IPv6 地址类型

类型 前缀 说明
全球单播地址 (GUA) 2000::/3 可在全球路由
唯一本地地址 (ULA) FC00::/7 类似 RFC 1918
链路本地地址 (LLA) FE80::/10 仅链路本地，不可路由
组播地址 FF00::/8 组播通信
任播地址 — 共享地址，最近路由器响应

IPv6 地址分配方法

方法 说明 适用场景
SLAAC (无状态地址自动配置) 路由器通告前缀，设备自生成 IID 简单部署
DHCPv6 有状态 DHCP 分配完整地址 需要地址追踪
DHCPv6 无状态 SLAAC + DHCP 分配额外信息（DNS 等） SLAAC + DNS
手动配置 静态配置 服务器、路由器

IPv6 地址规划

设计原则 说明
层次化分配 按地理/功能分配前缀，支持汇总
预留扩展 保留足够的前缀空间
ULA vs GUA 内部通信可使用 ULA，外部使用 GUA
安全考量 不使用 EUI-64（暴露 MAC 地址）

IPv6 迁移策略

策略 说明 适用场景
双栈 (Dual Stack) 同时运行 IPv4 和 IPv6 最常见迁移方式
隧道 (Tunneling) IPv6 over IPv4 或反之 过渡期
NAT64/DNS64 IPv6-only 网络访问 IPv4 服务 IPv6-only 部署
464XLAT IPv4-only 应用在 IPv6 网络上 移动运营商

IPv6 设计考量

考量 说明
ICMPv6 重要性 ICMPv6 承担更多功能（NDP、SLAAC、MLD）
NDP 安全 NDP 无认证，需 RA Guard、ND Inspection
扩展头 扩展头可能影响转发性能
MTU IPv6 路由器不分片，需 PMTUD
组播 IPv6 大量使用组播（替代广播）

QoS 设计

QoS 的商业驱动

QoS 不仅仅是技术问题——它是业务需求的直接反映。QoS 确保关键应用在网络拥塞时仍能获得所需的网络资源。

QoS 模型

模型 说明
Best-Effort 无 QoS 保障
IntServ (集成服务) 信令驱动（RSVP），端到端预留
DiffServ (区分服务) 基于标记的差异化处理，最常用

QoS 机制

机制 说明 目标
分类与标记 识别流量类型并标记 DSCP、802.1p
流量监管 限制流量速率 CAR、Policing
流量整形 缓冲超额流量 Shaping
排队 按优先级调度 LLQ、CBWFQ
拥塞避免 主动丢包避免拥塞 WRED
压缩 减少头部开销 cRTP、HC

DSCP 标记

DSCP 值 名称 类型 适用流量
46 (EF) 加速转发 高优先级 语音
40 (CS5) 信令 中高 呼叫信令
34 (AF41) 确保转发 中高 视频会议
26 (AF31) 确保转发 中 关键数据
18 (AF21) 确保转发 低中 一般数据
0 (DF) 默认 尽力而为 最佳努力

QoS 设计原则

原则 说明
分类信任边界 尽可能靠近源标记，不信任终端标记
端到端 QoS 全链路一致标记和调度
LLQ for Voice 语音使用低延迟队列
带宽保证 为每种流量类型保证带宽
分层 QoS 在不同层级应用不同策略

QoS 在 SD-WAN 中的应用

特性 说明
应用感知 自动识别应用并应用 QoS
动态队列 基于应用动态创建队列
路径选择 基于应用需求选择传输路径

网络管理与服务

网络管理功能域

功能域 说明
FCAPS 故障、配置、计费、性能、安全管理
监控 实时监控网络状态
日志 集中日志和事件关联
告警 基于阈值的主动告警
报告 容量规划和趋势分析

网络管理协议

协议 说明 使用场景
SNMP v2c/v3 简单网络管理协议 设备监控、轮询
NETCONF 网络配置协议 设备配置
RESTCONF RESTful API Web 应用集成
gNMI gRPC 管理接口 高性能遥测
Syslog 系统日志 事件日志
NetFlow/IPFIX 流量分析 流量监控
Streaming Telemetry 流式遥测 实时监控

遥测 vs 传统监控

对比 传统 SNMP 流式遥测
模式 轮询 推送
延迟 秒级 毫秒级
开销 高（大量轮询） 低（按需推送）
精度 低 高
适合场景 遗留设备 现代网络

网络编排

技术 说明
策略驱动网络 基于策略自动配置
意图驱动网络 (IBN) 声明业务意图，系统自动实现
闭环自动化 监控 → 分析 → 自动修复
网络分析 AI/ML 驱动的网络优化
