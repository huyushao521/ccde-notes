基础内容 (Foundation Topics)

IP 路由和转发概念回顾

路由协议的主要目标是作为交付机制，将数据包路由到目的地。端到端路由过程基于分布式数据库的概念：

概念 定义
RIB（路由信息库） 每个三层节点上维护的 IP 地址数据库，包含目的 IP 和下一跳 IP
FIB（转发信息库） 转发表，包含目的地址和到达该目的所需的接口

路由协议分为三类： - 链路状态协议（OSPF、IS-IS） - 路径矢量协议（BGP） - 距离矢量协议（RIP、EIGRP — 混合型）

链路状态路由 (Link-State Routing)

链路状态路由协议使用 Dijkstra 最短路径算法计算最佳路径。OSPF 和 IS-IS 是链路状态协议。

链路状态数据库 (LSDB) 构建过程

  1. 路由器发现邻居并建立邻接关系
  2. 交换链路状态通告 (LSA/LSP)
  3. 每个 LSA 包含路由器链路、接口、链路状态和成本信息
  4. 构建 LSDB
  5. 运行 Dijkstra 算法计算最短路径树 (SPT)

Hub-and-Spoke 拓扑中的链路状态设计

在 Hub-and-Spoke 拓扑中使用链路状态协议时，需要考虑：

问题 说明 解决方案
可扩展性 每个 Spoke 接收所有其他 Spoke 的链路状态信息 使用多区域/多泛洪域设计
次优路由 流量可能使用远程站点作为中转路径 ABR 之间需要非汇总链路交换特定路由信息
中转流量 Spoke 可能被用作 Spoke-to-Spoke 的中转 在 Spoke 路由器上设置 stub 区域

⚠️ 关键设计要点：在多区域设计中，ABR 之间需要一条非汇总链路来交换特定路由信息，避免使用 Spoke 站点作为中转路径。

OSPF 设计考量

OSPF LSA 类型

LSA 类型 名称 生成者 传播范围
Type 1 Router LSA 每台路由器 区域内
Type 2 Network LSA DR 区域内
Type 3 Summary LSA ABR 跨区域
Type 4 Summary ASBR LSA ABR 跨区域
Type 5 AS External LSA ASBR 整个 AS
Type 7 NSSA External LSA ASBR (NSSA 内) NSSA 内（转 Type 5 传出）

OSPF 区域类型

区域类型 特点 允许的 LSA
Backbone (Area 0) 核心区域，所有其他区域必须连接 所有类型
Normal Area 标准区域 所有类型
Stub Area 不接收外部路由（Type 5），用默认路由替代 Type 1, 2, 3
Totally Stub 不接收外部和跨区域路由，用默认路由替代 Type 1, 2
NSSA 不接收 Type 5，但允许 Type 7（自定义外部路由） Type 1, 2, 3, 7
Totally NSSA NSSA + 不接收 Type 3 Type 1, 2, 7

OSPF 网络类型

网络类型 DR/BDR 选举 适用场景
Broadcast 是 以太网
Point-to-Point 否 串行链路、点对点
Point-to-Multipoint 否 NBMA 网络（如帧中继）
Nonbroadcast (NBMA) 是 需要手动配置邻居

OSPF 快速收敛技术

技术 说明
SPF 延迟和抑制 控制 SPF 计算频率，避免频繁计算
增量 SPF (iSPF) 只重新计算受影响的部分，而非整棵 SPT
部分路由计算 (PRC) 只更新路由表，不重算 SPT
LSA 延迟 控制重新生成 LSA 的速率
BFD 提供亚秒级邻居故障检测
路由器 LSA 节流 限制 Type 1 LSA 生成频率

OSPF 路由汇总

汇总方向 位置 说明
区域间汇总 ABR 将区域内的路由汇总后通告到其他区域
外部路由汇总 ASBR 将外部路由汇总后通告到 OSPF 域

⚠️ 多个 ABR 上做汇总的风险：可能导致链路故障时的次优路由。任何在多个 ABR 上做汇总的设计都存在此问题。

IS-IS 设计考量

IS-IS vs OSPF 对比

对比项 IS-IS OSPF
层级 Level 1 (区域内)、Level 2 (区域间) Area 0 (骨干)、非骨干区域
路由器类型 L1、L2、L1/L2 内部路由器、ABR、ASBR
区域边界 链路上 路由器上
LSA 等价物 LSP (链路状态 PDU) LSA
DR 等价物 DIS (指定中间系统) DR
DIS 选举 优先级最高者（无备份） 优先级最高者（有 BDR）
网络类型 仅 Broadcast 和 Point-to-Point 多种网络类型
运行层 Layer 2 (数据链路层) Layer 3 (IP 层)
协议号/以太类型 以太类型 0xFEFE IP 协议号 89
MPLS-TE 支持 是 是
扩展性 高（TLV 结构易于扩展） 中（需要新 LSA 类型扩展）

IS-IS DIS vs OSPF DR

特性 IS-IS DIS OSPF DR
备份 无 BDR 有 BDR
被替换 可被更高优先级路由器替换 不会被替换（除非故障）
伪节点 生成伪节点 LSP 生成 Network LSA

IS-IS Overload Bit

Overload Bit 的作用： - 设置后，其他路由器不会通过该路由器转发中转流量 - 黑洞避免：在路由器启动时设置，防止在 LSDB 同步前被用作中转 - 流量工程：有选择地将流量引导到其他路径

IS-IS 层级设计

    ┌─────────── L2 Backbone ───────────┐
    │  L1/L2 ═══ L1/L2 ═══ L1/L2       │
    └──┬──────────┬──────────┬──────────┘
       │          │          │
    L1 Area    L1 Area    L1 Area
    (含 L1     (含 L1     (含 L1
    路由器)     路由器)     路由器)
  • L1 路由器只知道区域内的路由
  • L1/L2 路由器连接 L1 区域和 L2 骨干
  • L2 骨干连接所有区域

EIGRP 设计考量

EIGRP 核心概念

概念 说明
DUAL 算法 弥散更新算法，EIGRP 的核心算法
后继路由器 (Successor) 当前用于转发流量的下一跳路由器
可行后继路由器 (Feasible Successor) 备份路由，满足可行性条件 (FC)
可行性条件 (FC) 报告距离 (RD) < 可行距离 (FD)
可行距离 (FD) 到目的地的最小计算距离
报告距离 (RD) 邻居报告的到目的地的距离

EIGRP 数据包类型

类型 传输方式 说明
Hello 组播 发现和维护邻居关系
Update 组播/单播 传递路由更新（使用 RTP）
Query 组播 查询路由信息（使用 RTP）
Reply 单播 响应 Query（使用 RTP）
ACK 单播 确认可靠数据包

EIGRP Query 范围控制（关键设计！）

⚠️ EIGRP 最大的设计陷阱：如果不控制 Query 范围，任何拓扑变化都会导致大量 Query 泛洪，可能导致 SIA（Stuck-in-Active），延长收敛时间。

Query 范围控制方法：

方法 说明
路由汇总 在边界汇总路由，阻止 Query 传播到不需要的区域
EIGRP Stub 将路由器配置为 Stub，不向 Stub 路由器发送 Query
Stub 路由器类型 Receive-only、Connected、Static、Summary、Redistributed

EIGRP Stub 路由器

Stub 路由器不会作为中转路由器，Hub 路由器不会向 Stub 发送 Query。

Stub 类型 通告的路由
Receive-only 不通告任何路由，只接收
Connected 通告直连路由
Static 通告静态路由
Summary 通告汇总路由
Redistributed 通告重分发路由

路由汇总 (Route Summarization)

汇总的好处

  1. 减少路由表大小 — 节省内存和 CPU
  2. 减少泛洪范围 — 限制 LSA/LSP 传播
  3. 降低不稳定性传播 — 网络某部分的路由翻动不会影响其他部分
  4. 加快收敛 — 减少需要处理的信息量
  5. 信息隐藏 — 隐藏拓扑细节，提高安全性

汇总的风险

风险 说明 缓解方法
次优路由 汇总后可能选择非最优路径 在多个汇总点之间使用特定路由
黑洞 汇总路由指向的路由器可能无法到达某些子网 仔细规划汇总范围
故障检测延迟 汇总隐藏了具体路由状态 在需要快速检测的链路上不使用汇总

流量工程和路径选择 (Traffic Engineering and Path Selection)

路径选择方法

方法 协议 说明
基于度量的路径选择 IGP 通过调整链路成本影响路径选择
基于策略的路径选择 BGP 通过 BGP 属性控制流量路径
MPLS-TE RSVP-TE 显式路径，按需建立隧道
策略路由 (PBR) 静态 基于源地址、端口等策略转发

IGP 度量调整

度量类型 说明
OSPF Cost 基于带宽，可手动调整
IS-IS Metric 默认所有接口为 10，需要手动调整
EIGRP Metric 复合度量（带宽+延迟+可靠性+负载），默认仅带宽+延迟

OSPF Cost 计算

OSPF Cost = 参考带宽 / 接口带宽

默认参考带宽 = 100 Mbps
- 10 Mbps 链路: Cost = 10
- 100 Mbps 链路: Cost = 1
- 1 Gbps 链路: Cost = 1 (需要调整参考带宽)
- 10 Gbps 链路: Cost = 1 (需要调整参考带宽)

建议: auto-cost reference-bandwidth 10000 (10G)

BGP 路由 (BGP Routing)

BGP 基础

BGP 是路径矢量路由协议，是互联网的核心路由协议。

BGP 类型 说明
eBGP 外部 BGP，不同 AS 之间的 BGP 会话
iBGP 内部 BGP，同一 AS 内的 BGP 会话

BGP 属性 (Attributes)

属性 类型 说明 影响方向
Weight Cisco 专有 本地路由器有效，最高优先选 出口流量
Local Preference 非传递 整个 AS 内有效，越高越优先 出口流量
AS Path 公认必遵 经过的 AS 列表，越短越优先 入口流量
Origin 公认必遵 路由来源 (IGP < EGP < Incomplete) -
MED 可选非传递 多出口鉴别器，越低越优先 入口流量
Community 可选传递 标记路由，用于策略 -
Next Hop 公认必遵 下一跳地址 -

BGP 路径选择顺序

  1. Weight（最高优先）
  2. Local Preference（最高优先）
  3. 本地起源（本路由器起源的路由优先）
  4. AS Path（最短优先）
  5. Origin（IGP 优先）
  6. MED（最低优先）
  7. eBGP over iBGP
  8. 最近 IGP 邻居
  9. ** oldest route**（最旧路由优先）
  10. Router ID（最低优先）

影响出口流量的方法

方法 属性 说明
Weight Cisco 专有 仅本路由器有效
Local Preference 标准 整个 AS 内有效
AS Path Prepend 标准 影响其他 AS 的入口流量选择
MED 标准 影响邻居 AS 的入口流量选择

影响入口流量的方法

方法 说明
AS Path Prepend 在 AS Path 中添加自己的 AS 号多次，使路径变长
MED 设置较低的 MED 值，使邻居优先选择此路径
Community 使用 community 标记路由，配合邻居策略

BGP 作为企业核心路由协议

💡 BGP 作为企业核心路由协议越来越受欢迎，原因包括： - 更好的可扩展性 - 精细的路径控制能力 - 与 IGP 解耦的灵活策略 - 支持多租户（VPNv4/VPNv6 地址族）

BGP vs IGP 作为核心

对比项 BGP IGP (OSPF/IS-IS)
可扩展性 极高（互联网规模） 中到高
收敛速度 较慢 快
路径控制 精细（属性） 粗粒度（度量）
策略支持 丰富 有限
复杂度 高 中
适合场景 大型企业、多数据中心 中小企业、园区

BGP 可扩展性选项

技术 说明 使用场景
路由反射器 (RR) 减少 iBGP 全互联会话数量 大量 iBGP 对等体
BGP 联盟 将 AS 分为子 AS 超大规模网络
对等体组 共享策略的一组邻居 简化配置
对等体模板 继承式配置模板 简化配置
BGP RTC 基于路由目标的约束 VPN 路由过滤

路由重分发 (Route Redistribution)

⚠️ 路由重分发是网络设计中最容易出问题的地方之一。

重分发设计原则

原则 说明
单向重分发 只从一个协议向另一个协议重分发，避免路由环路
双点双向重分发 需要额外机制防止路由环路（如 tag、前缀列表）
使用 Tag 为重分发路由添加标记，防止反向重分发
使用前缀列表 精确控制重分发的路由
度量设置 重分发时设置合理的初始度量值

路由环路防止方法

OSPF → EIGRP:    加 Tag 100
EIGRP → OSPF:    过滤 Tag 100（防止反向重分发）
                  加 Tag 200
OSPF ← EIGRP:    过滤 Tag 200

企业路由设计建议

如何选择正确的路由协议

因素 OSPF IS-IS EIGRP BGP
可扩展性 高 高 高（需正确设计） 极高
收敛速度 快（优化后） 快（优化后） 快（配合汇总） 较慢
路径控制 度量 度量 度量 精细（属性）
复杂度 中 中 低到中 高
厂商支持 标准 标准 Cisco（现已开放） 标准
MPLS-TE 是 是 否 否
适合场景 园区、数据中心 大型服务提供商 中小企业 大型企业核心

设计原则总结

  1. 没有标准设计 — 每个设计决策都由业务需求驱动
  2. 信息隐藏 — 使用汇总和区域/层级设计减少信息传播
  3. 快速收敛 — 使用 BFD、优化计时器、增量 SPF 等技术
  4. 故障隔离 — 通过模块化和区域设计限制故障影响范围
  5. 避免中转流量 — 使用 Stub 区域、路由策略防止不需要的中转
  6. 简单性 — 在满足需求的前提下选择最简单的方案
