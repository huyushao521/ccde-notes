基础内容 (Foundation Topics)

IP 路由和转发概念回顾

路由协议的主要目标是作为交付机制，将数据包路由到目的地。端到端路由过程基于分布式数据库的概念：

概念 定义
RIB（路由信息库） 每个三层节点上维护的 IP 地址数据库，包含目的 IP 和下一跳 IP
FIB（转发信息库） 转发表，包含目的地址和到达该目的所需的接口

路由协议分为三类： - 链路状态协议（OSPF、IS-IS） - 路径矢量协议（BGP） - 距离矢量协议（RIP、EIGRP — 混合型）

链路状态路由 (Link-State Routing)

链路状态路由协议使用 Dijkstra 最短路径算法计算最佳路径。OSPF 和 IS-IS 是链路状态协议。

链路状态数据库 (LSDB) 构建过程

  1. 路由器发现邻居并建立邻接关系
  2. 交换链路状态通告 (LSA/LSP)
  3. 每个 LSA 包含路由器链路、接口、链路状态和成本信息
  4. 构建 LSDB
  5. 运行 Dijkstra 算法计算最短路径树 (SPT)

Hub-and-Spoke 拓扑中的链路状态设计

在 Hub-and-Spoke 拓扑中使用链路状态协议时，需要考虑：

问题 说明 解决方案
可扩展性 每个 Spoke 接收所有其他 Spoke 的链路状态信息 使用多区域/多泛洪域设计
次优路由 流量可能使用远程站点作为中转路径 ABR 之间需要非汇总链路交换特定路由信息
中转流量 Spoke 可能被用作 Spoke-to-Spoke 的中转 在 Spoke 路由器上设置 stub 区域

⚠️ 关键设计要点：在多区域设计中，ABR 之间需要一条非汇总链路来交换特定路由信息，避免使用 Spoke 站点作为中转路径。

OSPF 快速收敛技术

技术 说明
SPF 延迟和抑制 控制 SPF 计算频率，避免频繁计算
增量 SPF (iSPF) 只重新计算受影响的部分，而非整棵 SPT

OSPF 路由汇总

汇总方向 位置 说明
区域间汇总 ABR 将区域内的路由汇总后通告到其他区域
外部路由汇总 ASBR 将外部路由汇总后通告到 OSPF 域

⚠️ 多个 ABR 上做汇总的风险：可能导致链路故障时的次优路由。任何在多个 ABR 上做汇总的设计都存在此问题。

IS-IS Overload Bit

Overload Bit 的作用： - 设置后，其他路由器不会通过该路由器转发中转流量 - 黑洞避免：在路由器启动时设置，防止在 LSDB 同步前被用作中转 - 流量工程：有选择地将流量引导到其他路径

EIGRP 设计考量

EIGRP 核心概念

概念 说明
DUAL 算法 弥散更新算法，EIGRP 的核心算法
后继路由器 (Successor) 当前用于转发流量的下一跳路由器
可行后继路由器 (Feasible Successor) 备份路由，满足可行性条件 (FC)
可行性条件 (FC) 报告距离 (RD) < 可行距离 (FD)
可行距离 (FD) 到目的地的最小计算距离
报告距离 (RD) 邻居报告的到目的地的距离

EIGRP 数据包类型

类型 传输方式 说明
Hello 组播 发现和维护邻居关系
Update 组播/单播 传递路由更新（使用 RTP）
Query 组播 查询路由信息（使用 RTP）
Reply 单播 响应 Query（使用 RTP）
ACK 单播 确认可靠数据包

EIGRP Query 范围控制（关键设计！）

⚠️ EIGRP 最大的设计陷阱：如果不控制 Query 范围，任何拓扑变化都会导致大量 Query 泛洪，可能导致 SIA（Stuck-in-Active），延长收敛时间。

Query 范围控制方法：

方法 说明
路由汇总 在边界汇总路由，阻止 Query 传播到不需要的区域
EIGRP Stub 将路由器配置为 Stub，不向 Stub 路由器发送 Query
Stub 路由器类型 Receive-only、Connected、Static、Summary、Redistributed

EIGRP Stub 路由器

Stub 路由器不会作为中转路由器，Hub 路由器不会向 Stub 发送 Query。

Stub 类型 通告的路由
Receive-only 不通告任何路由，只接收
Connected 通告直连路由
Static 通告静态路由
Summary 通告汇总路由
Redistributed 通告重分发路由

路由汇总 (Route Summarization)

汇总的好处

  1. 减少路由表大小 — 节省内存和 CPU
  2. 减少泛洪范围 — 限制 LSA/LSP 传播
  3. 降低不稳定性传播 — 网络某部分的路由翻动不会影响其他部分
  4. 加快收敛 — 减少需要处理的信息量
  5. 信息隐藏 — 隐藏拓扑细节，提高安全性

汇总的风险

风险 说明 缓解方法
次优路由 汇总后可能选择非最优路径 在多个汇总点之间使用特定路由
黑洞 汇总路由指向的路由器可能无法到达某些子网 仔细规划汇总范围
故障检测延迟 汇总隐藏了具体路由状态 在需要快速检测的链路上不使用汇总

流量工程和路径选择 (Traffic Engineering and Path Selection)

路径选择方法

方法 协议 说明
基于度量的路径选择 IGP 通过调整链路成本影响路径选择
基于策略的路径选择 BGP 通过 BGP 属性控制流量路径
MPLS-TE RSVP-TE 显式路径，按需建立隧道

IGP 度量调整

度量类型 说明
OSPF Cost 基于带宽，可手动调整
IS-IS Metric 默认所有接口为 10，需要手动调整
EIGRP Metric 复合度量（带宽+延迟+可靠性+负载），默认仅带宽+延迟

OSPF Cost 计算

OSPF Cost = 参考带宽 / 接口带宽

默认参考带宽 = 100 Mbps
- 10 Mbps 链路: Cost = 10
- 100 Mbps 链路: Cost = 1
- 1 Gbps 链路: Cost = 1 (需要调整参考带宽)
- 10 Gbps 链路: Cost = 1 (需要调整参考带宽)

建议: auto-cost reference-bandwidth 10000 (10G)

BGP 路由 (BGP Routing)

BGP 基础

BGP 是路径矢量路由协议，是互联网的核心路由协议。

BGP 类型 说明
eBGP 外部 BGP，不同 AS 之间的 BGP 会话
iBGP 内部 BGP，同一 AS 内的 BGP 会话

BGP 属性 (Attributes)

属性 类型 说明 影响方向
Weight Cisco 专有 本地路由器有效，最高优先选 出口流量
Local Preference 非传递 整个 AS 内有效，越高越优先 出口流量
AS Path 公认必遵 经过的 AS 列表，越短越优先 入口流量
Origin 公认必遵 路由来源 (IGP < EGP < Incomplete) -
MED 可选非传递 多出口鉴别器，越低越优先 入口流量
Community 可选传递 标记路由，用于策略 -
Next Hop 公认必遵 下一跳地址 -

BGP 路径选择顺序（完整 13 条）

⚠️ BGP 选路是自上而下逐条比较：只有当前一条完全相等（tie），才会进入下一条。这是排查"我改了属性但流量不走"的核心逻辑——你改的属性可能排在第 6 条，而路由在第 2 条就已经分出胜负了。

# 判据 方向 谁控制 说明
1 Weight（高优先） 本机出方向 本机 Cisco 私有，不传递，只在本路由器生效；本地有效值 0–65535
2 Local Preference（高优先） AS 内出方向 本 AS 通过 iBGP 传遍全 AS，默认 100；控制"我出去走哪个出口"的主力工具
3 本地起源（locally originated） — 本机 network / redistribute / aggregate-address / default-originate 产生的路由优先于从邻居学到的同前缀
4 AS_PATH（短优先） 入方向 上游/自己 prepend 经过 AS 数最少；可数 AS_SET 长度（不同厂商对 {} 计法不同）
5 Origin（IGP < EGP < Incomplete） 入方向 上游 i 优于 e 优于 ?；重分发来的路由是 ?，比 network 声明的 i 劣
6 MED（低优先） 入方向 自己设置、上游采纳 默认只在同一邻居 AS 之间比较；跨 AS 比较需 bgp always-compare-med
7 eBGP 优于 iBGP — — 同一前缀从 eBGP 和 iBGP 都学到时，选 eBGP（外部路径更"接近源"）
8 到 NEXT_HOP 的 IGP metric 最小 出方向 IGP 设计 常被称为 hot-potato routing；数据中心里这一条会悄悄改写你精心设计的 MED
9 最老的 eBGP 路由 — — 两条都是 external 时，先收到的优先；用于抑制路由抖动（flapping 惩罚的软实现）
10 Router ID 最小 — 手工规划 比较 BGP Router ID；RR 场景比较 Originator ID
11 Cluster List 最短 — RR 拓扑 路由反射器环境专用，簇列表越短越优
12 邻居 IP 地址最小 — 物理编址 最后的兜底判据；依赖接口地址规划，不要指望它可预测
13 multipath（并列安装） — maximum-paths 前面 1–12 全等时，若开启 ECMP 则多条同时进 RIB 做负载分担，而不是只留一条

13 条的分层理解（比背顺序更重要）

  • 第 1–2 条：本地意志。 Weight 只在单机有效（适合"这台机器临时改道"），Local Preference 才是 AS 级出口策略的正规工具。设计上应尽量只用一个，混用会让排障逻辑无法收敛。
  • 第 3–6 条：路径来源与长度。 这一段是策略生效的主战场，也是上游运营商能影响你的部分。AS_PATH prepend 和 MED 都在这段。
  • 第 7–8 条：IGP 反噬。 很多人以为 1–6 条定了就定了，实际第 8 条会把 MED 的效果直接推翻——因为两条外部路径的 IGP 开销不同，MED 相等时按 IGP 选，MED 生效时也要先确认 IGP 度量是否一致。
  • 第 9–12 条：平局兜底。 这些不应成为设计依据，只应作为"发现自己在靠第 10 条选路"的告警信号——那意味着前面的策略没写清楚。

厂商差异（设计文档里必须写清，否则交接必出错）

概念 Cisco 华为 / H3C Juniper FRR / Arrcus
本机优先级 Weight（私有） Preferred Value 无（用 LP 代替） 无 Weight
AS 内出口策略 Local Preference Local Preference local-preference local-preference
跨 AS 比较 MED 需 bgp always-compare-med 默认就比较 默认就比较 需显式配置

影响出口流量的方法（我出去走哪条）

方法 属性 生效范围 说明
Weight Cisco 专有 仅本路由器 单机临时改道用，不传递
Local Preference 标准、非传递 整个 AS 内 出口策略的主力工具，排在选路第 2 条
本地起源 — 本机 本机 network 声明的路由优先于学来的同级路由
IGP metric to NEXT_HOP — 本机 选路第 8 条，常被忽略但真实生效

影响入口流量的方法（别人进来走哪条）

方法 生效范围 说明
AS Path Prepend 其他 AS 在 AS Path 中重复自己的 AS 号，使路径变长；入口策略的主力工具
MED 邻居 AS 设置较低 MED 让邻居优先选此路径；默认只在同一邻居 AS 内比较
Community 邻居 / 上游 打标记，由上游按其策略执行（需上游配合，最灵活但最不可控）

⚠️ 出口策略（Weight / LP）只在本 AS 内有效，改不了别人的回程路径；入口策略（AS_PATH / MED / Community）必须依赖对端采纳才生效。改了一半的流量工程最常见的结果是单向不对称。

BGP 作为企业核心路由协议

💡 BGP 作为企业核心路由协议越来越受欢迎，原因包括： - 更好的可扩展性 - 精细的路径控制能力 - 与 IGP 解耦的灵活策略 - 支持多租户（VPNv4/VPNv6 地址族）

BGP vs IGP 作为核心

对比项 BGP IGP (OSPF/IS-IS)
可扩展性 极高（互联网规模） 中到高
收敛速度 较慢 快
路径控制 精细（属性） 粗粒度（度量）
策略支持 丰富 有限
复杂度 高 中
适合场景 大型企业、多数据中心 中小企业、园区

BGP 可扩展性选项

技术 说明 使用场景
路由反射器 (RR) 减少 iBGP 全互联会话数量 大量 iBGP 对等体
BGP 联盟 将 AS 分为子 AS 超大规模网络
对等体组 共享策略的一组邻居 简化配置
对等体模板 继承式配置模板 简化配置

路由重分发 (Route Redistribution)

⚠️ 路由重分发是网络设计中最容易出问题的地方之一。

重分发设计原则

原则 说明
单向重分发 只从一个协议向另一个协议重分发，避免路由环路
双点双向重分发 需要额外机制防止路由环路（如 tag、前缀列表）
使用 Tag 为重分发路由添加标记，防止反向重分发
使用前缀列表 精确控制重分发的路由
度量设置 重分发时设置合理的初始度量值

路由环路防止方法

OSPF → EIGRP:    加 Tag 100
EIGRP → OSPF:    过滤 Tag 100（防止反向重分发）
                  加 Tag 200
OSPF ← EIGRP:    过滤 Tag 200

设计原则总结

  1. 没有标准设计 — 每个设计决策都由业务需求驱动
  2. 信息隐藏 — 使用汇总和区域/层级设计减少信息传播
  3. 快速收敛 — 使用 BFD、优化计时器、增量 SPF 等技术
  4. 故障隔离 — 通过模块化和区域设计限制故障影响范围
  5. 避免中转流量 — 使用 Stub 区域、路由策略防止不需要的中转
  6. 简单性 — 在满足需求的前提下选择最简单的方案

实战案例

案例一：MED 设了却完全不生效

场景：总部双出口，ISP-A 为主链路、ISP-B 为备。工程师在边界路由器上给 ISP-A 的出向路由设了 MED 50（明显更低），期望全网立即切回 A。结果核心层流量纹丝不动，仍然走 B。

排查过程：

  1. 核心交换机查 BGP 表，两条默认路由的 Local Preference 都是 100、AS_PATH 长度都是 1 —— 第 2、4 条平局。
  2. 关键点：ISP-A 和 ISP-B 是两个不同的邻居 AS。MED 是"可选非传递"属性，默认只在同一邻居 AS 的多条路径之间比较。不同 ISP 的 MED 根本不进入比较，第 6 条被直接跳过。
  3. 于是落到第 7 条（都是 eBGP，平局）→ 第 8 条（到 NEXT_HOP 的 IGP metric 最小），B 侧下一跳在 IGP 里更近，胜出。MED 白设了。

修复：改用 Local Preference。LP 排在第 2 条，比 MED 早四位，且在 AS 内统一生效：

! 边界路由器，从 ISP-A 学到的路由提高 LP
route-map FROM-ISP-A permit 10
 set local-preference 200
! ISP-B 保持默认 100

教训：调属性前先确认这条属性排在选路顺序的第几位，以及它是否参与比较。MED 的两个常见失效原因是"跨邻居 AS 不可比"和"路径在第 4 条就已经分出胜负，根本轮不到第 6 条"。

案例二：iBGP 里有路由，路由表里没有

场景：数据中心两台 spine 与 WAN 边缘建立 eBGP，spine 之间跑 iBGP。边缘学到互联网路由后通过 iBGP 传给两台 spine，配置看起来完全正常，show ip bgp 能看到全部路由 —— 但 show ip route 里没有，业务不通。

排查过程：

  1. show ip bgp 8.8.8.0 显示路由是 valid 但不是 best，或者 best 却未装表。
  2. 看下一跳：iBGP 默认不修改 NEXT_HOP，边缘把自己的地址作为下一跳传过来。spine 上查这个地址的 IGP 路由 —— 不存在。BGP 要求下一跳必须可达（能递归到直连/IGP 路由）才认为路径有效。
  3. 这就是 iBGP 著名的"下一跳不可达"陷阱：BGP 表有、路由表没有，中间那层是 IGP 没覆盖。

修复（两种，选一种）：

方案 配置 代价
next-hop-self 边缘对 iBGP 邻居 neighbor x.x.x.x next-hop-self 边缘必须承载全部回程流量，成为单点带宽瓶颈
IGP 覆盖下一跳 确保所有 BGP 下一跳网段都进 IGP（通常用 loopback 建会话 + 全网 IGP 可达） 要求 IGP 设计完整，但转发路径更优

大型 DC 多用第二种（下一跳不变 + IGP 承载可达性），因为可以让流量走最短路径；小型网络用 next-hop-self 更简单。

案例三：双点双向重分发，出口翻转后再没切回来

场景：并购整合后两张网共存，OSPF 域和 EIGRP 域在两个点做了双向重分发。某天 A 点链路抖动一次，业务流量全部改从 B 点出去，之后 A 点恢复也再没切回来，部分区域还出现 TTL 耗尽的环路。

根因：从 EIGRP 学到的路由被重分发进 OSPF 后，在 OSPF 域内以"外部路由"（Type 5）形式传播，其度量被换算成一个很有竞争力的值；B 点又把这条路由回注 EIGRP，形成路由回流。结果是 OSPF 域内的选路依据被另一张网的路由污染，A 点恢复后本地路径反而不优。

修复（标准三件套）：

! 1. 重分发时打 tag
route-map EIGRP-TO-OSPF permit 10
 set tag 100
! 2. 反向重分发时按 tag 过滤，杜绝回流
route-map OSPF-TO-EIGRP deny 10
 match tag 100
route-map OSPF-TO-EIGRP permit 20
! 3. 加前缀列表，只允许必须互通的网段

验证方法：show ip route 逐条看 AD 与 next-hop，traceroute 确认不再绕行；恢复 A 点后观察路径是否回到预期出口。

设计取舍：双点双向重分发几乎没有必要。除非是并购过渡期，否则应做单向重分发（一张网作为核心、另一张网作为边缘），把复杂度和风险一次降下来。

设计陷阱

陷阱 典型现象 根因 规避方法
用 MED 做跨 ISP 出口选择 改 MED 完全无效 MED 默认只在同一邻居 AS 之间比较 出口策略用 Local Preference
靠第 10–12 条决定路径 重启或加邻居后流量漂移 前面所有判据都平局，靠 Router ID 抽签 显式用 LP / AS_PATH 拉开差距

实战经验总结

  1. 属性调不动，先数顺序。 BGP 排障第一步永远是"路由在第几条分出胜负"，而不是继续加策略。show ip bgp <prefix> 看 LP、AS_PATH、Origin、MED 四项就能定位 90% 的问题。
  2. MED 和 LP 二选一。 同一张网里两者混用，等于给排障埋两颗雷。出路策略只留 LP，入口策略只留 AS_PATH + Community。
  3. 路由协议的数量要少。 双点双向重分发的复杂度远超它带来的收益；能用 BGP 统一核心就不要叠加 IGP 转换层。
  4. IGP 的度量会偷偷改写 BGP 决策。 第 8 条（IGP metric to next-hop）是真实世界最常"打脸"的一条，做流量工程时必须把 IGP 度量一起纳入设计。
  5. 汇总必须配兜底。 汇总带来的可扩展性是真的，汇总带来的黑洞和环路也是真的；null0 汇总路由是必须项，不是可选项。
