第 7 章：二层技术 (Layer 2 Technologies)

本章涵盖主题

  • 二层核心技术：STP、VLAN、Trunk、链路聚合、mLAG、FHRP

基础内容 (Foundation Topics)

二层核心技术 (Layer 2 Core Technologies)

网络设计师需要了解、理解并能够正确做出设计决策的二层核心技术包括：

  1. 生成树协议 (STP)
  2. 虚拟局域网 (VLAN)
  3. Trunking（中继）
  4. 链路聚合
  5. 多机箱链路聚合 (mLAG)
  6. 首跳冗余协议 (FHRP)

生成树协议 (Spanning Tree Protocol, STP)

STP 是经典二层交换网络环境中最成熟和最常用的控制协议，用于防止二层桥接环路。它通过阻塞冗余 L2 接口来提供无环拓扑。

STP 版本

版本 标准 特点
802.1D 传统 STP 基础版本，收敛较慢
802.1W 快速 STP (RSTP) 增强收敛时间，支持大规模部署
802.1S 多生成树 (MST) 将多个 VLAN 聚合到同一 STP 实例，减少 CPU 负载，支持超大规模部署

STP 增强特性

特性 功能 部署位置
Loop Guard 防止备用端口或根端口在没有 BPDU 的情况下被选举 分布层下行端口
Root Guard 防止外部或下游交换机成为根桥 分布层下行端口
BPDU Guard 在启用了 PortFast 的端口收到 BPDU 时禁用该端口 接入层端口
BPDU Filter 阻止在 PortFast 端口上发送或接收 BPDU 接入层端口

💡 Cisco 还开发了 PVST+ 和 Rapid PVST+，为每个 VLAN 运行独立的 STP 实例。

VLAN 和 Trunking

VLAN 是一种网络虚拟化技术，提供广播域的逻辑分离和策略控制。VLAN 还在二层提供一定程度的故障隔离。

Trunking 是允许在单条物理链路上承载多个 VLAN 的协议，使 VLAN 可以跨交换机扩展。

⚠️ 设计最佳实践：VLAN 不应跨多台接入交换机。但这只是一般建议——某些设计需要 VLAN 跨交换机扩展（如多数据中心虚拟机迁移场景）。

链路聚合 (Link Aggregation)

IEEE 802.3ad 标准，将多条物理链路组合为一条逻辑链路。

优势： - 成本效益高的带宽增加方案（无需硬件升级） - 消除单点故障，增强链路级可靠性 - 行业标准，支持多厂商互操作

两种连接模型：

模型 说明
单机箱链路聚合 两个网络节点之间的点对点连接
多机箱链路聚合 (mLAG) 上游交换机以"交换机集群"模式部署，提供更高级别的链路和路径弹性

⚠️ 每个单独的流量受限于该流量使用的成员链路速度（基于负载均衡哈希算法）。

💡 Cisco VSS（虚拟交换系统）将分布交换机对转换为逻辑单台交换机，消除了 STP 和 FHRP 的需求。

首跳冗余协议 (FHRP) 和 STP

FHRP 提供首跳三层网关的透明故障转移能力。两台或多台三层设备作为一个组，代表一个虚拟三层网关。

FHRP 选项对比

特性 HSRP VRRP GLBP
标准 Cisco 专有 IEEE 标准 Cisco 专有
IPv6 支持 是 (v2) 是 (v3) 是
认证 是 是 是
负载分担 多个 HSRP 组 多个 VRRP 组 原生支持
默认 Hello 计时器 3 秒 1 秒 3 秒
虚拟 IP 可与接口 IP 不同 可与接口 IP 不同 与接口 IP 不同
BFD 支持 是 是 是

FHRP 和 STP 对齐设计（关键！）

⚠️ 最常见的网络设计错误之一：STP 根桥未与 FHRP 活动实例对齐。

正确的对齐设计（图 7-3）： 1. 分布交换机之间的链路配置为三层链路 2. VLAN 不跨交换机扩展 3. STP 根桥与每个 VLAN 的活动 FHRP 实例对齐 4. 接入层到分布层的上行链路从 STP 角度都是转发状态

未对齐的后果： - 流量经过额外跳到达活动 FHRP 网关 - 次优路由 - 在大多数情况下被视为糟糕的设计

💡 当使用 GLBP 作为 FHRP 时，由于 ARP 响应分配是随机的，不如 HSRP 或 VRRP 确定性强。

二层 LAN 常见设计模型

基于 STP 的模型

四种经典 STP 拓扑：

1. 环路三角形拓扑 (Looped Triangle)

    DSW1 ═══════ DSW2
     │  ╲        ╱  │
     │   ╲      ╱   │
     │    ╲    ╱    │
     └───── ASW ────┘
  • 设计顾虑：STP 限制了所有可用上行链路的利用，效率不高
  • 适用场景：单归属端点，无高带宽和快速收敛需求

2. 无环路倒 U 型拓扑 (Loop-Free Inverted U)

    DSW1          DSW2
     │            │
     │            │
     └──── ASW ────┘
  • 设计顾虑：如果一台分布交换机或上行链路故障，会引入单点故障
  • 适用场景：双归属端点（NIC 绑定）或不需要低 MTTR 的端点

3. 环路方形拓扑 (Looped Square)

    DSW1 ═══════ DSW2
     │            │
     │            │
     └──── ASW ────┘
  • 设计顾虑：大量接入层流量可能穿越交换机间链路到达活动 FHRP
  • 适用场景：非关键单/双归属端点，无高带宽需求

4. 无环路 U 型拓扑 (Loop-Free U)

    DSW1 ═══════ DSW2
     │            
     │            
     ASW ────────┘
  • 设计顾虑：无法在超过一对接入交换机上扩展相同 VLAN
  • 适用场景：单/双归属端点，高转发容量和较快收敛需求，不需要跨交换机扩展 VLAN

⚠️ 共同限制：所有 STP 模型都依赖 STP 避免环路，依赖 FHRP 计时器收敛。这些依赖导致节点或链路故障时收敛时间增加。调优和对齐 STP 和 FHRP 计时器是推荐做法。

四种拓扑综合对比

拓扑 设计顾虑 适用场景
环路三角形 STP 限制上行链路利用 单归属端点，无高带宽需求
无环路倒 U 分布交换机故障引入单点故障 双归属端点，不需要低 MTTR
环路方形 流量穿越交换机间链路到达 FHRP 非关键端点，无高带宽需求
无环路 U 无法扩展 VLAN 超过一对交换机 需要高转发容量和快速收敛的场景

交换机集群模型 (Switch Clustering Based / Virtual Switch)

交换机集群显著改变了接入层和分布层之间的二层设计模型。

核心思想：一对上游分布交换机从接入交换机角度看是一台逻辑（虚拟）交换机。

优势： - 消除对 STP 和 FHRP 的依赖，消除相关收敛延迟 - 所有上行链路处于转发状态 - 一个虚拟 IP 网关，两台交换机都转发流量（Active-Active） - 最大化带宽容量，利用所有上行链路 - 支持跨接入交换机安全扩展二层 VLAN，无需担心二层环路 - 比传统 STP 设计更简单、可靠、易管理、可扩展

局限性 — 脑裂 (Split-Brain)： - 两台或更多集群设备同时充当主设备 - 通常由集群链路故障引起 - 使用双活检测 (Dual Active Detection) 机制来缓解

交换机堆叠 (Stacking)

交换机堆叠是集群的另一种形式： - 多台物理交换机通过 StackWise 互联电缆连接 - 选举主交换机 - 作为单一对象管理，使用单一 IP 管理地址和单一配置文件 - 可创建 EtherChannel 连接和 MEC（多机箱 EtherChannel）

菊花链接入交换机 (Daisy-Chained Access Switches)

⚠️ 通常作为临时解决方案使用，可能引入以下问题： - 双活 HSRP（脑裂情况） - 使用分布交换机 1 作为活动 FHRP 网关的设备可能丢失 50% 的返回流量

💡 当建议替代方案时，必须确保新设计不会在故障场景中引入新的问题。否则新引入的问题将超过方案的好处。
