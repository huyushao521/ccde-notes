基础内容 (Foundation Topics)

零接触部署 (Zero-Touch Provisioning, ZTP)

ZTP 使网络设备能够在无需人工现场配置的情况下自动部署。

ZTP 工作流程

1. 设备启动 → 无配置
2. 通过 DHCP 获取 IP 地址
3. DHCP 选项提供配置文件 URL
4. 设备下载配置文件
5. 应用配置 → 网络连接
6. 可选：注册到控制器/管理平台

ZTP 的好处

好处 说明
减少部署时间 从小时级降到分钟级
降低人为错误 模板化配置减少配置错误
远程部署 无需工程师现场操作
一致性 所有设备使用相同模板
可审计 配置变更可追踪

On-Prem ZTP vs Cloud ZTP

类型 特点 适用场景
本地 ZTP 本地 DHCP/TFTP 服务器 内部网络、安全敏感环境
云 ZTP 通过云平台管理 多分支企业、SD-WAN

基础设施即代码 (Infrastructure as Code, IaC)

IaC 是通过代码（机器可读的定义文件）管理和配置基础设施的过程，替代手动配置。

IaC 核心原则

原则 说明
幂等性 (Idempotency) 多次执行相同代码产生相同结果
版本控制 基础设施定义存储在版本控制系统中
声明式 vs 命令式 声明式描述"想要什么"，命令式描述"怎么做"
可重用 模块化设计，可复用
可审计 变更历史可追踪

IaC 工具

工具 类型 适用场景
Ansible 声明式、无代理 网络设备配置
Terraform 声明式 多云/混合基础设施
Python (Netmiko/NAPALM/Nornir) 命令式 网络自动化脚本
Git 版本控制 配置版本管理

Ansible 核心概念

概念 说明
Playbook YAML 格式的自动化任务定义
Inventory 目标设备清单
Module 执行特定功能的代码单元
Role 可复用的任务集合
Variables 参数化配置

CI/CD Pipelines

CI/CD 是一种通过自动化来构建、测试和部署应用程序的方法。

CI/CD 阶段

阶段 说明 在网络中的应用
CI (持续集成) 代码合并到主干，自动构建和测试 网络配置变更提交后自动验证
CD (持续交付) 自动将变更部署到预生产环境 网络配置推送到预生产环境
CD (持续部署) 自动将变更部署到生产环境 网络配置自动推送到生产环境

网络中的 CI/CD 流程

开发者修改配置 → Git 提交 → CI 触发
→ 自动验证语法 → 自动测试（lab 环境）
→ 代码审查 → 合并到主干
→ CD 部署到预生产 → 验证
→ CD 部署到生产 → 监控

CI/CD 在网络中的好处

好处 说明
变更速度 从天/周级降到分钟级
质量 自动测试减少人为错误
可回滚 快速回滚到上一个版本
可审计 所有变更记录在版本控制中
一致性 消除手动配置的漂移

网络自动化 API

API 类型 说明 典型应用
NETCONF XML 格式的网络配置协议 设备配置管理
RESTCONF RESTful API，JSON/XML 格式 现代 Web 应用集成
gNMI gRPC 网络管理接口 高性能遥测和配置
REST API HTTP/HTTPS RESTful API 控制器集成
CLI/SNMP 传统方式 遗留系统兼容

数据模型

模型 说明
YANG 数据建模语言，描述网络配置和状态
IETF YANG 模型 标准 YANG 模型
OpenConfig 厂商无关的 YANG 模型
原生模型 厂商特定 YANG 模型
