附录 B：跨章对比速查

各章内部的对比表讲"这一章里的选项"，本页讲跨章的同类技术横向对比。 用法：先判断"要解决哪一类问题"，再找到对应矩阵，按维度逐行比较，最后看"选择线"。

B.1 路由协议选型（第 8 章）

维度 OSPF IS-IS EIGRP
承载协议 IP（协议号 89 上跑 IP） 直接在二层（CLNS），与 IPv4/v6 无关 IP（协议号 88）
扩展性 区域划分，单区域建议 ≤ 100–200 台 层级（L1/L2）天然，超大网更稳 扁平，靠 stub/汇总限制查询
收敛 快（SPF），可配 BFD + 节流 快，大网收敛优于 OSPF 快（DUAL），但查询扩散是隐患
IPv6 OSPFv3 需单独进程/配置 单拓扑原生双栈（扩展性好） 支持，但生态主要在 Cisco
多厂商 全厂商支持 运营商/大网支持好，中小企业配置门槛高 基本只有 Cisco
流量工程 弱（需 TE 扩展） 弱（需 TE 扩展） 弱（K 值不是 TE 工具）
运维熟悉度 最高，人才储备最多 中等（运营商背景熟悉） 中（Cisco 环境熟悉）

选择线： - 企业园区/分支 → OSPF（人才与工具生态决定） - 运营商/超大规模数据中心 → IS-IS（层级与稳定性） - 纯 Cisco 存量、团队只熟 EIGRP → 可以保留，但必须配 stub + 汇总限制查询范围

B.2 核心承载 IGP 还是 BGP（第 8 章）

维度 IGP 承载核心 iBGP 承载核心
策略能力 弱（metric/区域） 强（LP、MED、community、AS-PATH）
规模上限 数百台 数千前缀/数千邻居（配 RR）
收敛速度 快 慢（需调优 + BFD + 前缀抑制）
运维复杂度 低 高（RR、下一跳、路由反射、表项）
典型场景 园区、中型企业 大型企业、DCI、多运营商、需要策略的核心

选择线：核心是否需要按业务/按链路做策略分流？需要 → BGP；只需要最短路径 → IGP。

B.3 二层传输服务（第 6 章）

服务 拓扑 是否学 MAC 客户侧看到 典型用途
EPL / 专线 点到点，端口独占 否 一根网线 极低时延、带宽保障、老系统迁移
EVPL / VPWS 点到点，VLAN 复用端口 否 一根网线 多点汇聚、成本敏感的点到点
EPLAN 多点，端口型 是 一个局域网 多站点大二层
EVPLAN / VPLS 多点，VLAN 型 是 一个局域网 同上，端口可复用
EVPN（含 PBB-EVPN） 多点，控制面学习 控制面学 一个局域网 新建大二层、DCI、需要多归属

选择线： - 纯 IP 业务 → 不用二层服务（用 L3VPN / SD-WAN） - 真的需要二层 → 能用 EVPL/EVPN 点对点或小范围 就不要用 VPLS 全互联

B.4 站点互连方案（第 6、9、17 章）

方案 层次 加密 运维成本 适用
专线 / 暗光纤 L1 无（需自加） 高（按月租） 极稳定、时延敏感、合规要求物理隔离
MPLS L3VPN L3 默认不加密 中（运营商 SLA） 多站点、需要 QoS/SLA、业务稳定
Internet + SD-WAN L3 Overlay 内建（IPsec） 低（自运维策略） 分支众多、带宽弹性、云访问
DMVPN / FlexVPN L3 Overlay 内建 中（自建 Hub） 无 SD-WAN 预算、Hub-Spoke
大二层（VPLS/EVPN） L2 无 高（广播/STP/MTU） 特殊场景（迁移、老旧系统）

选择线：业务是否需要运营商 SLA？需要 → MPLS；不需要且站点多 → SD-WAN；需要二层 → 重新质疑这条需求。

B.5 隔离与分段（第 7、9、10、15 章）

技术 粒度 跨设备 是否做检查 适用
VLAN 广播域 需 Trunk 否 同一交换机内部分组
Private VLAN 端口级（isolated/community） 需 Trunk 否 接入侧隔离（多租户、访客）
VRF 路由表 是 否（只是隔离） 跨站点业务隔离、合规边界
SGT / TrustSec 标签（与地址解耦） 是 否（授权 ≠ 检查） 大规模策略随身份走
VXLAN 分段（L3 VNI） VRF 级 是（Overlay） 否 数据中心/园区 fabric
微分段（主机/服务侧） 工作负载级 是 是（策略引擎） 数据中心东西向精细控制
有状态防火墙 会话级 是 是 所有主要域边界

选择线：隔离 ≠ 检查。要"看不见"用 VRF/VLAN；要"过不去"必须有检查点。

B.6 远程访问与 VPN（第 10 章）

方案 拓扑 加密 可见性 适用
IPsec 远程访问（IKEv2） 客户端到网关 是 全隧道时好 员工远程办公（传统）
DMVPN Hub-Spoke（mGRE + NHRP） 是 好 分支互连，Phase 3 支持分支直通
FlexVPN 统一 IKEv2 框架 是 好 新建首选，替代 DMVPN
GET VPN 组加密，无隧道 是（组密钥） 好（保留原 IP 头） MPLS WAN 上的加密，保留 QoS/组播
ZTNA 应用到用户 是（TLS） 应用级 替代"拨入网段"，最小权限
SASE 云 PoP 融合 是 云侧统一 多分支 + 云 + 移动办公统一策略

选择线：要不要给"网段"？要 → VPN；只给"应用" → ZTNA/SASE。

B.7 组播 RP 方案（第 13 章）

方案 冗余 配置一致性 适用
静态 RP 无 各设备必须完全一致 小网、可预测
BSR 有（候选 RP 选举） 自动 中型网、多 RP
Anycast-RP（MSDP） 有（就近） 需 MSDP 全互联 多区域、单域内
Phantom RP 有（环回地址备份） 需 BGP 承载 大型/运营商，Anycast + RP 冗余
SSM 不需要 RP 简单 有明确源的一对多（推荐新建）

选择线：源与接收者可枚举 → SSM（省掉整个 RP 体系）；不能 → 用 Anycast-RP/Phantom RP 做冗余。

B.8 二层冗余与多机箱（第 7、15 章）

技术 冗余层 活跃链路 故障收敛 适用
STP/RSTP/MST 物理链路 单活（部分） 秒级~数十秒 小型接入
StackWise / VSS（堆叠） 单控制面 多活 快，但控制面同生共死 接入层、小核心
vPC / M-LAG 双控制面 多活 快（对端独立） 汇聚/核心，推荐
路由化（三层到接入） 协议 多活（ECMP） 快，无 STP 大型园区/DC

选择线：故障域。堆叠把两台合成一台（简单但一起挂），vPC 保持独立（复杂但更韧）。

B.9 QoS 架构（第 14 章）

模型 机制 扩展性 适用
IntServ 逐流 RSVP 预留 差（状态随流数量增长） 极小规模、强保障需求
DiffServ 分类 + 标记 + 每跳 PHB 好 企业主流
MPLS TE 显式路径 + 预留 中（需全网红薯 TE 域） 运营商/大型骨干
SD-WAN 策略 应用识别 + 链路选择 + SLA 探测 好 分支 + 多云

选择线：企业只做 DiffServ（分类在信任边界、队列在各跳一致、限速只用在必需处）；跨域时靠 映射表（DSCP↔EXP/TC）保持一致。

B.10 互联网多宿主（第 16 章）

模型 冗余 入向控制 复杂度 适用
单宿主单链路 无 — 低 非关键业务
单宿主双链路 链路级 无 低 小企业
双宿主（双 ISP） ISP 级 弱（靠 MED/prepend，最终由对端决定） 中 主流企业
双宿主 + 双设备 + 双出口 全冗余 同上 高（会话状态、NAT、选路） 关键业务

选择线：入向不可控 + 状态不可复制是两条硬约束。能做的是"降级可用"，不是"零中断"。

B.11 自动化分工（第 12 章）

工具/层 管什么 不管什么 适用
Ansible 设备配置下发（无代理、SSH） 状态一致性、回滚 存量设备、渐进自动化
Terraform 资源生命周期（声明式，有 state） 设备内细粒度配置 云资源、可重建环境
NSO / 厂商控制器 模型驱动配置、合规校验 跨厂商统一模型（需抽象） 大型多厂商网络
CI/CD（GitLab/Actions） 变更流程、审查、测试 网络语义正确性 所有自动化项目的骨架

选择线：先有流程再有工具。没有 Git、评审、回滚与测试的自动化，只是"更快的脚枪"。

B.12 IPv6 迁移（第 14 章）

方式 优点 缺点 适用
双栈 最平滑、无翻译损失 运维双份（监控、ACL、安全策略） 主流选择
NAT64/DNS64 存量 IPv4 无需改 有状态翻译，破坏端到端、影响部分应用 过渡期、移动网络
隧道（6in4/DS-Lite） 快速接通孤岛 MTU、路径不可见、故障定界难 临时/过渡

选择线：能双栈就双栈；只有明确"无法升级的存量"才用翻译，且要评估应用兼容性。
