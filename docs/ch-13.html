基础内容 (Foundation Topics)

组播基础

组播地址范围

范围 地址 说明
本地网络控制 224.0.0.0/24 不被路由器转发
全网控制 224.0.1.0/24 被路由器转发
SSM 范围 232.0.0.0/8 源特定组播
GLOP 233.0.0.0/8 基于 AS 号分配
管理范围 239.0.0.0/8 私有组播（类似 RFC 1918）

IP 组播到 MAC 地址映射

组播 MAC = 01:00:5E:XX:XX:XX

IP 组播地址 239.1.2.3
→ 二进制: 11101111.00000001.00000010.00000011
→ 取后 23 位: 0000001.00000010.00000011
→ MAC: 01:00:5E:01:02:03

问题: 32 个 IP 组播地址映射到同一 MAC 地址（5 位被丢弃）

⚠️ 5 位重叠问题：由于 IP 组播地址的后 28 位中只有 23 位映射到 MAC，32 个不同的 IP 组播地址会映射到同一 MAC 地址。

二层组播

技术 说明
CGMP (Cisco 组管理协议) Cisco 专有，已过时
IGMP Snooping 交换机侦听 IGMP 报告，限制组播泛洪
IGMPv1/v2/v3 组播组成员管理协议
MLD IPv6 的 IGMP 等价物

IGMP 版本对比

特性 IGMPv1 IGMPv2 IGMPv3
组成员加入 加入组 加入组 加入组
组成员离开 无离开消息 有离开消息 有离开消息
特定源 (SSM) 否 否 是
查询器选举 基于 PIM DR 最低 IP 最低 IP
查询间隔 60s 125s 125s

三层组播路由

RPF (反向路径转发)

RPF 是组播路由的核心概念。路由器收到组播包后，检查源地址——只有当入接口是到达源地址的最优路径接口时，才转发该包。

源 → R1 → R2 → 接收者
         ↓
    RPF 检查: 入接口是否是到源的最优路径?
    是 → 转发
    否 → 丢弃

PIM (协议无关组播)

PIM 模式 特点 适用场景
PIM Dense Mode (PIM-DM) 推模式，泛洪-修剪 密集用户，少量路由器
PIM Sparse Mode (PIM-SM) 拉模式，显式加入 稀疏用户，大规模网络
PIM-SSM 源特定组播 已知源的组播
Bidirectional PIM (BiDir) 双向组播 多源到多组

PIM-SM 工作流程

1. RP (汇聚点) 配置
2. 接收者发送 IGMP 加入 → 最后一跳路由器
3. 最后一跳路由器向 RP 发送 PIM (*, G) Join
4. 源开始发送 → 第一跳路由器向 RP 注册
5. RP 发送 PIM (S, G) Join 到源
6. 组播流量沿共享树 → 切换到最短路径树 (SPT)

SPT 切换 (Shortest Path Tree Switchover)

💡 PIM-SM 默认在接收者收到第一个组播包后，从共享树 (RP Tree) 切换到最短路径树 (Source Tree)，获得更优路径。

RP (Rendezvous Point) 放置

RP 发现方法 特点
静态 RP 手动配置，简单但不灵活
Auto-RP Cisco 专有，自动发现 RP
BSR (自举路由器) 标准，自动发现 RP
Anycast-RP 多个 RP 共享同一 IP，负载分担和冗余

RP 放置原则

原则 说明
靠近源 减少源到 RP 的延迟
靠近接收者 减少接收者到 RP 的延迟
中心位置 在源和接收者之间折中
冗余 使用 Anycast-RP 或 BSR 提供备份

Anycast-RP

        RP-1 (10.0.0.1)          RP-2 (10.0.0.1)
         /  MSDP peer  \         /                \
        /               \       /                  \
    源 →                  接收者                  接收者

    RP-1 和 RP-2 使用相同 IP (Anycast)
    通过 MSDP 交换 (S, G) 信息
优势 说明
负载分担 不同接收者选择不同的 RP
冗余 一个 RP 故障，另一个接管
快速故障切换 IGP 收敛即切换

域间组播

方案 说明
MSDP (组播源发现协议) 在不同 PIM 域之间交换源信息
MBGP (组播 BGP) 为组播提供独立的 RPF 路径
Anycast-RP with MSDP 跨域 RP 冗余

高级组播设计

Phantom RP

用于二层网络中无真正三层路由的场景。创建一个虚拟 RP 地址，实际不存在物理设备，通过 VRRP/HSRP VIP 实现。

Live-Live (Multicast Live-Live)

通过两条不同路径同时发送相同组播流，接收者选择最优路径。当一个路径故障时，接收者无感知切换。

要求 说明
双路径 两条不重叠的物理路径
独立 RP 每条路径独立 RP
唯一组地址 每条路径使用不同的组播组地址
接收者多加入 接收者同时加入两个组

FHRP-Aware PIM

当使用 FHRP（HSRP/VRRP）时，只有 Active 路由器发送 PIM Join。当 Active 故障切换到 Standby 时，新的 Active 需要重新建立 PIM 状态。

特性 说明
消除 PIM Join 抖动 Standby 到 Active 切换时无需重新 Join
快速收敛 与 FHRP 故障切换同步
支持 HSRP v2/v3 支持 IPv4 和 IPv6
